# Worklab UX/UI Audit — Findings

> Generated by `src/__tests__/playwright/ux-audit.spec.js` on 2026-04-23. The spec
> walks every route at three viewports (390 × 844, 768 × 1024, 1440 × 900),
> screenshots each, and emits a JSON manifest at
> `test-results/ux-audit/findings.json`. This document curates the JSON into
> reviewable findings.

**Scope:** 46 route × viewport snapshots covering all 11 user-facing routes
plus the New-task modal at mobile. Source: ephemeral worklab instance seeded
with one task per status, one agent, one skill, two KB entries.

**Headline numbers (from `findings.json` summary):**

| Metric | Count |
|---|---|
| Route × viewport snapshots | 46 |
| Snapshots with horizontal overflow | 2 (both = TaskDetail with long content) |

The runtime-clean a11y/console numbers don't mean the app is perfect — they mean
the structural smoke checks pass. The interesting finding is the overflow root

error handling, destructive actions) but which code analysis surfaces.

## A. Responsive

### A1 — [HIGH, NEW] CSS-grid `1fr` column traps long content on TaskDetail

**Symptom (visible at every viewport).** When a task description contains a long
unbreakable string (long URL, long key inside a fenced code block), the Brief
panel grows beyond its grid column:

- 390 px viewport: `<html>` scrollWidth = **945 px** vs. innerWidth 390 px →
  ~555 px horizontal overflow. The Brief panel slides off-screen to the right.
  See `test-results/ux-audit/mobile-task-detail-long.png`.
- 768 px viewport: scrollWidth = **957 px** vs. 768 px innerWidth.
  See `test-results/ux-audit/tablet-task-detail-long.png`.
- 1440 px viewport: the Brief panel slides **under** the right sidebar
  (Workflow / Discussion); the right sidebar floats above the description text.
  See `test-results/ux-audit/desktop-task-detail-long.png`.

**Root cause.** `.task-detail-grid` and `.task-main-stack` / `.task-side-stack`
all use bare `1fr` or implicit `auto` columns
(`src/ui/src/styles.css:280-284, 706-711, 1173-1176`). A `1fr` grid track
without `minmax(0, ...)` will *expand* to fit non-wrapping content (the classic
CSS Grid pitfall). The same shape exists in `.page-stack` and `.section-stack`,
so any long content in any route can trigger the same break.

**Fix (Phase 1).** Add `grid-template-columns: minmax(0, 1fr)` to
`.page-stack`, `.section-stack`, `.task-main-stack`, `.task-side-stack`. In the
`@media (max-width: 1020px)` block, change `.task-detail-grid` and
`.settings-grid` to `minmax(0, 1fr)` too. The desktop rule
`grid-template-columns: minmax(0, 1fr) minmax(320px, 380px)` already does this
for the left column on desktop — the overflow on desktop is the *child stack*,
not the outer grid, so the same fix applies.

### A2 — [HIGH, CONFIRMED] Code/event blocks lack a forced wrap on small screens

`pre`/`.code-panel` declares `white-space: pre-wrap` (`styles.css:739-747`),
which is good — but `<pre>` ignores `overflow-wrap: anywhere`, so a
single 80+ character string with no spaces (URLs, long JSON keys) still expands
the box. Visible in the same TaskDetail screenshots as A1: the long URL and
long JSON key push the `<pre>` wide. Need
`word-break: break-word; overflow-wrap: anywhere;` on `pre`/`.code-panel` at
viewport ≤ 720 px (and arguably always, since the gain in readability outweighs
the loss for code).

### A3 — [MED, CONFIRMED] `.app-rail` keeps `height: 100vh` after collapsing

`styles.css:75` sets `height: 100vh` on `.app-rail`. The 1020 px media query
overrides to `height: auto` (`styles.css:1135-1141`), so this is actually
harmless — older mobile browsers that don't support the override would
layout-thrash, but Chromium target audience renders correctly. Lower priority
than originally graded; documenting for completeness.

### A4 — [MED, CONFIRMED] No safe-area padding on `.app-header`

`styles.css:207` doesn't account for `env(safe-area-inset-top)`. Not visible in
the desktop / tablet / 390 × 844 (iPhone 14 baseline) screenshots, but a
notched-phone PWA install would clip the page eyebrow under the notch. Cheap
to fix; bundle into Phase 1.

### A5 — [LOW, CONFIRMED] Knowledge card-mode label column too narrow at < 360 px

Fixed `72px` label column (`styles.css:1228`). 360 px viewport leaves ~270 px
content width — readable but cramped for tag lists. `minmax(60px, 30%)` plus
a stacked fallback at ≤ 360 px addresses this. No 320 px viewport in the
audit (only 390 px); confirmed via code reading only.

## B. User-friendly

### B1 — [SUPERSEDED] NewTaskModal already has executor + reviewer fields

The plan called for adding executor/reviewer pickers to the modal. They are
already there (`src/ui/src/components/NewTaskModal.jsx:50-69`), confirmed in
`test-results/ux-audit/mobile-modal-newtask.png`. The fields default to
"Unassigned" / "No reviewer" — what's missing is **last-used recall** so a
user with one or two agents doesn't re-pick on every task. Defer to Phase 2 as
a smaller change: persist last selection in `localStorage` and pre-select.

### B2 — [HIGH, CONFIRMED] Form save errors are silent

Visible in the source (`TaskDetail.jsx:85-90`, `KbEdit.jsx`, `SkillEdit.jsx`,
`AgentEdit.jsx`, `Settings.jsx`, `Providers.jsx`): every patch promise is
`await`ed without a try/catch and the form flips to read-only on resolve. A
non-200 response throws, the function bails, the user sees nothing change.
Phase 2 fix: a `useFormSave` hook that exposes `{ saving, error, save }` and
inline-renders an error near the action row.

### B3 — [HIGH, CONFIRMED] Destructive deletes fire on first click

`TaskDetail.jsx:99` uses `confirm("Delete this task?")` (browser dialog).
`AgentEdit`, `SkillEdit`, `KbEdit` have similar `class="danger"` buttons but
no native `confirm()` — they fire immediately. Browser confirm is OK for now
but inconsistent across surfaces. Phase 2: ship a `<ConfirmButton>` that
toggles label to "Click again to delete" with a 4-s timeout, wire everywhere.

### B4 — [MED, CONFIRMED] Empty-state and loading-state share one surface

`Activity.jsx:44` renders `<div class="surface-panel meta">No runs yet.</div>`
in both empty and loading-after-load conditions. Knowledge has a similar
fallthrough. Need a distinct `<EmptyState icon title body cta>` component.

### B5 — [MED, CONFIRMED] No drag-drop rollback toast on Kanban PATCH failure

`Kanban.jsx:36` optimistically updates and silently reverts. A small toast
helper (Phase 2 plan §5) addresses this and serves as the error-surface
substrate for B2 and elsewhere.

### B6 — [INFO] Every kanban card shows "No executor"

Visible in `mobile-tasks.png` and `desktop-tasks.png`. With one agent seeded
and ample real estate on the card, the persistent "No executor" label is
information-poor. Either show the executor name when one is set, or hide the
"No executor" string and replace with a subtle warning glyph. Touched in
Phase 3 (executor avatars on cards).

## C. Interconnected

### C1 — [HIGH, CONFIRMED] No reverse links between domains

Audited four route pairs:

- KB entry → tasks/agents that reference it (none).
- Agent → recent runs by this agent (none — data exists in `agent_logs`).
- Skill → agents that have it allowlisted (none).
- Provider → agents using it (none).

All four are Phase 3 work — small REST endpoints + a "Used by" / "Recent runs"
section in the corresponding edit screen.

### C2 — [HIGH, CONFIRMED] Activity rows can't deep-link to a specific run

`Activity.jsx:61` generates `<a href="#/tasks/{id}">Open task</a>`.
TaskDetail reads no query params. Phase 3: change href to
`#/tasks/{id}?run={runId}`, parse in TaskDetail, scroll the matching
`<RunTimelineCard>` into view and open it.

### C3 — [MED, CONFIRMED] Kanban cards don't surface executor / reviewer

Visible in `desktop-tasks.png` — every card shows status badge only. Adding
small initial-circle avatars below the title (Phase 3) closes the gap.

### C4 — [MED, CONFIRMED] Comment author name is not linked to agent profile

`CommentAuthor.jsx` renders the agent's display name as plain text. Wrap in
`<a href="#/agents/{name}">` in Phase 3.

### C5 — [MED, FROM ROADMAP] Inline journal in TaskDetail

Phase 6 roadmap (`docs/plans/phase-6-roadmap.md:30`) specced this and deferred
it. Lift back into Phase 3 — closes the loop between "what the SDK did" (event
timeline) and "what the agent decided" (journal).

## D. Accessibility

### D1 — [LOW, RUNTIME-CLEAN] Icon-only buttons audit

Runtime walk found 0 buttons or links with no text and no `aria-label`. The
existing components hand-roll labels well. Manual code-read still flags two
pieces:

- `CommentAuthor.jsx` SVG icons — they sit next to a name, so accessible name
  is satisfied at the parent level. Add `aria-hidden="true"` to the SVGs to
  prevent SR double-announce.
- Brand mark `.brand-mark` — decorative; same treatment.

### D2 — [MED, CONFIRMED] NewTaskModal lacks Escape-to-close + focus trap

`NewTaskModal.jsx:34-35`. Phase 4 work via a `useFocusTrap` hook + `Escape`
key handler.

### D3 — [INFO] No `:focus-visible` style on most interactive elements

Buttons inherit browser default focus ring. Acceptable on Chromium dark theme
but inconsistent. Phase 4: standardise with `:focus-visible { outline: 2px
solid var(--accent); outline-offset: 2px }` on `button`, `a`, `select`,
`input`, `textarea`.

## What the harness cannot see

The audit is a smoke layer. It does not catch:

- **Multi-step flows** — the harness loads each route once. Real flows
  (create → assign → run → review) need scenario tests, currently only
  partially covered by `ui-regressions.spec.js`.
- **Async/SSE rendering** — the 350 ms settle is sufficient for synchronous
  routes but can miss late-arriving events (e.g., a streaming run output).
- **Color-contrast WCAG ratios** — the `contrastSmoke` check only flags exact
  color matches between text and background. A future iteration can lift in
  axe-core for proper contrast scoring.
- **Touch target sizes** — no check for `min-height: 44px` on tap targets.
  The kanban "Refresh" / "+ New task" buttons render at ~32 px in the mobile
  screenshot, below WCAG 2.5.5 advisory.

These belong in the next harness iteration, not the first.
